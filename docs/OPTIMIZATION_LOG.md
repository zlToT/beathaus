# v6 · 段落粒子与搓碟去鬼叫

> 用户验收 v5 后提出：相机再下移、机器人动作别整齐、螺旋/波形因画布翻倍变小；并新增搓碟怪声排查与段落粒子（Drop 气球）。

## 一、v6 改造总览

| # | 问题 | v6 处理 |
|---|---|---|
| 1 | 相机再下移 | 默认静止 y 5→4；全景 y 7→6、lookAt 下移，更平视 |
| 2 | 机器人动作一样 | 按人设给不同频率/幅度/弹跳，咧嘴还会高举挥手 |
| 3 | 螺旋/波形变小 | 固定像素振幅/半径改为相对画布比例，恢复原视觉占比 |
| 4 | 搓碟有怪声 | 单帧角度限幅、平滑 0.55→0.35、速率限幅 ±2→±1.5 |
| 5 | 段落无差异粒子 | 新建 SectionFX：Drop 气球+彩带，Build 聚拢，各段落光点不同 |
| 6 | 激光点位不对 | 发射点从舞台中部(y7,z0)移到大屏上边(y11.3,z-6.2)，下压角度加大斜射观众 |
| 7 | 收起面板时其他面板还在 | 收起时顶部栏（当前曲目/实时信息）与右侧颜色拾取器一起淡出隐藏，展开恢复 |

## 二、逐项改造

### 1. 相机再下移

- 默认静止镜头 y 5→**4**（orbit / beat 同步）；全景 overview y 7→**6**、lookAt y 4→3，整体更贴近舞台、平视。

### 2. 机器人动作差异化

- 新增 `ACTIONS` 配置，按 type 区分动作：
  - **爱心眼**：慢节奏、小幅度（害羞）。
  - **墨镜耳机**：缓慢点头、小幅度（冷酷）。
  - **独眼雷达**：快速左右张望（headY 幅度大）、中弹跳。
  - **咧嘴笑**：大幅快摆 + 高弹跳，且右臂会**高举过头挥手**。

### 3. 螺旋/波形恢复占比

- 根因：v5 把大屏画布从 1024 翻到 2048，但螺旋半径系数（17）、波形振幅（170/80）写死像素，在大画布上相对变小。
- 改为相对画布比例：螺旋 r 系数 `W*0.0166`、波形振幅 `H*0.33 / H*0.16`、中心光点 `H*0.023`，四种模式视觉占比恢复；频谱保持不变。

### 4. 搓碟去鬼叫

- 核心搓碟逻辑此前未改，怪声来自手势快速拨动时速率瞬间冲到 ±2（2 倍速/快倒放的尖锐声）。
- 三重处理：
  - **单帧角度限幅**：每次移动角度变化限制在 ±0.5 rad，杜绝一次大跳；
  - **平滑更柔**：速率平滑系数 0.55→**0.35**；
  - **速率限幅收紧**：±2→**±1.5**；
  - dt 也限制在 8ms~50ms，避免极端时间间隔。

### 5. 段落粒子（新模块 SectionFX）

- 新建 `js/stage/SectionFX.js`，由 main.js 在段落确认切换时触发：
  - **Drop**：16 个彩色气球（带高光和细绳）从观众席慢悠悠飘上，同时 110 片彩带从舞台上方撒下；
  - **Build**：220 个光点向舞台中心加速聚拢上升（蓄力感）；
  - **Intro**：少量轻柔上升光点；
  - **Break**：稀疏缓慢光点；
  - **Groove**：稳定流动光点。
- 气球/彩带均为对象池，飘出/落地即回收，不持续产生。

# v5 · 机器人差异化与频谱去糊

> 用户验收 v4 后提出 4 点，重点是让四个机器人不再"天线宝宝"，并继续解决频谱糊、全景构图和面板收起细节。

## 一、v5 改造总览

| # | 问题 | v5 处理 |
|---|---|---|
| 1 | 收起时箭头留在原地 | 箭头 + 面板整体下滑，面板出屏、箭头停在屏幕最底边缘可点 |
| 2 | 频谱还是糊 | Bloom 阈值提高/强度降低、柱子稀疏、绘制分辨率翻倍 |
| 3 | 全景相机太高、上方空一大块 | 相机降高度、平视舞台，构图饱满 |
| 4 | 四个机器人长得一样 | 爱心眼 / 墨镜耳机 / 独眼雷达 / 咧嘴笑四种造型 |

## 二、逐项改造

### 1. 收起时箭头跟随

- 把箭头与面板包进 `#bottom-dock`，收起时对整个 dock 做 `translateY(calc(100% - 32px))`：
  - 面板完全滑出屏幕；箭头跟随下滑，停在屏幕最底边缘（pb-3 + 箭头高，露出朝上的「▲」）。
- 点底边箭头即展开，不会出现"面板走了、箭头停在半空"的错位。

### 2. 频谱再去糊

**根因**：v4 只统一了柱体颜色，但 Bloom 后处理 threshold 仅 0.15、strength 0.9，大屏稍亮的柱子就被晕开，这是"还是糊"的主因。

**v5 三管齐下**：
- **Bloom**：threshold 0.15→**0.35**、strength 0.9→**0.7**，灯光/霓虹照常发光，大屏中等亮度的频谱不再被大面积晕开。
- **柱子稀疏**：单侧 40→**30**，柱间 gap 加大，去掉最易过曝的白色亮帽。
- **绘制高清**：大屏离屏 Canvas 1024×512 → **2048×1024**，柱体边缘更锐利。

### 3. 全景平视构图

- overview 相机 y 10→**7**、lookAt y 3→**4**，z 22，由俯视改为平视舞台中部。
- 大屏与舞台在画面中居中饱满，消除上方大片空区；保留轻微浮动。

### 4. 四个机器人差异化

- 四个机器人按站位各设造型（仅改头部，身体/动作一致）：
  1. **爱心眼**（x=−7.5）：两只心形眼睛（`THREE.Shape` 心形 + ShapeGeometry），固定粉色。
  2. **墨镜耳机**（x=−2.6）：头顶耳机头梁（半圆环）+ 两侧耳罩，眼睛是一条横向墨镜 LED。
  3. **独眼雷达**（x=2.6）：一只大眼睛居中，头顶十字雷达随时间旋转。
  4. **咧嘴笑**（x=7.5）：宽咧嘴 + 三颗白色方块牙，保留天线。
- 跟随主色的发光材质统一收集（`glowMats`），setColor 时整体更新；爱心眼固定粉色不跟随。

### 6. 彩虹循环 = 渐变激光

- 移除 v3 的舞台后方垂直灯带（InstancedMesh）。

# v3 · 视觉与体验打磨

> 用户验收 v2 后，结合 4 张截图提出 9 点（含补充「前沿灯不需要这么长」）。先「对表」确认方向，再一次性落地。

## 一、v3 改造总览

| # | 问题 | v3 处理 |
|---|---|---|
| 1 | Tooltip 显示不全 / 被遮挡，宽屏底部出现横向滚动 | 改为挂 body 的全局 JS Tooltip，自动避开边缘 |
| 2 | 进度条只剩一个 Cue 标签时点不掉 | 修复重绘标记冲突（真 bug） |
| 3 | 频谱没居中、绿黄高频柱糊 | 低频居中、高频向两侧对称展开；Bars 模式噪点减弱 |
| 4 | 机器人数量与光柱不对应 | 3 → 4 个，分别站在四个光柱正下方 |
| 5 | 缺少演唱会场景光线条 | 新增 AmbientBeams：扫射激光 / 彩虹垂直灯带 |
| 6 | 机器人脚下没有立体感 | 每个机器人脚下独立抬高发光平台 |
| 7 | （补充）舞台前沿灯太长 | 前沿发光条 28 → 12，只在中央一段 |
| 8 | 全景俯视角度不对 | 改为舞台正对面看台视角，可见整个场景 + 轻微浮动 |

## 二、逐项改造

### 1. 全局 JS Tooltip（不再被裁剪 / 遮挡）

**v2 问题**

- 旧 Tooltip 用纯 CSS `[data-tip]::after` 实现，渲染在触发元素内部：
  - 顶部信息面板、右侧拾取器的提示会被容器边缘 / 视口截断（图 1、图 2）。
  - 面板 `overflow-x-auto` 会裁掉超出部分的提示。
- 宽屏下控制面板出现横向滚动条。

**v3 方案**

- 新增 `js/ui/Tooltip.js`：一个 `#global-tooltip` 挂到 **body**，通过事件委托（`mouseover` + `closest('[data-tip]')`）统一驱动。
- 定位基于目标元素 `getBoundingClientRect()`：
  - 默认在元素上方居中；上方空间不足（< 6px）自动翻到下方。
  - 水平方向 clamp 到视口内（左右各留 6px），不会被截断。
  - `pointer-events: none`、`z-index: 9999`，浮在所有控件之上。
- 滚动 / 窗口缩放时立即隐藏，避免提示停在错位。
- 移除旧的 `[data-tip]::after` 系列 CSS（含 header 向下、#color-picker 向左的特殊定位），改由全局样式 `#global-tooltip` 承担。

**宽屏滚动**

- 经 headless Chrome 在 1500 宽实测：三列（Deck A / 混音台 / Deck B）完整显示，无横向滚动条。
- 窄屏（内部宽度不足 1060）仍保留 `overflow-x-auto` 横向滚动，符合预期。

---

### 2. 修复单个 Cue 标签点不掉（真 bug）

**v2 问题**

- 进度条上只剩一个 Cue 标签时，怎么点都不消失。

**根因**

- `_renderCues()` 用「Cue 列表指纹」（各点时间 join）与 `cueLayer.dataset.key` 对比来决定是否重绘。
- 「强制重绘」的标记用的是空字符串 `''`，而删除最后一个 Cue 后列表指纹**也恰好是空字符串**，两者相等 → 判定「无需重绘」，数据已删除但视觉标签残留。

**v3 修复**

- 强制重绘标记改为不可能与指纹冲突的常量 `'FORCE'`（打点、标签删除两处）。
- 任意数量（含 1 个、最后一个）Cue 标签均可正常点掉。

---

### 3. 频谱中心镜像 + 提升清晰度

**v2 问题**

- 频谱柱从左到右排列，视觉重心偏左、看起来没居中；绿色 / 黄色高频柱发糊。

**v3 方案**

- `_bars()` 重写为**中心对称镜像**：

## 二、逐项改造

### 1. 播放键复用 + 多 Cue 点 + 去掉 Stop

**v1 问题**

- 播放、暂停、Stop 三个按钮，且「暂停」与「Cue」效果看起来一样（都会回到某处），用户无法理解。
- Cue 只有一个，且打点即跳转。

**v2 方案**

- **播放键复用**：一个按钮承担播放 / 暂停，按钮文字随状态切换（播放中显示「暂停」，停止时显示「播放」）。
- **删除 Stop 按钮**：停止 = 暂停后再 seek，无独立存在必要。
- **多 Cue 点**：
  - 暂停 / 播放中均可打点；播放中打点**不打断**播放。
  - 每个 Cue 在进度条上渲染为一个**可点击的标签**（带小三角的霓虹标记），点击标签即删除该 Cue。
  - 播放**正向越过**某个 Cue 时，自动停在该 Cue（CDJ 的「Cue 点自动暂停」）。
  - seek、搓碟经过 Cue **不触发**自动暂停（避免误触发）。
  - Cue 去重：0.4s 内重复打点只保留一个。

**技术实现**

- `Deck`：`cuePoints: number[]`；`addCue()` / `removeCueAt(t)` / `checkCueAutoStop()`。
- 位置跟踪改为「积分位置」`_pos`（见第 2 点），Cue 自动暂停基于「上一帧位置 < Cue ≤ 当前位置」的正向穿越判定。
- `DeckPanel`：`_renderCues()` 每帧同步标签数量与位置；标签 `pointerdown` 阻止冒泡（不触发 seek），`click` 删除。

**验证**

- seek 到 9s 打点 → 标签 1 个；再 seek 到 3s 打点 → 标签 2 个。
- seek 回 0 播放，4.5s 后自动停在 `00:03`，按钮恢复「播放」。
- 点击 3s 标签 → 标签 2→1，位置不变（未触发 seek）。

### 2. 搓碟：物理跟随，可倒放

**v1 问题**

- 旧逻辑把「指针角度变化」直接映射成一个放大的变速比，且只取正向；手指轻轻一转，角度变化被放大成极端变速，产生「鬼叫」；也无法倒放。

**v2 方案（真实碟片物理）**

- 以 **33⅓ rpm 黑胶的基准角速度** `PLATTER_OMEGA ≈ 3.49 rad/s` 为参照：
  - `手势角速度 ω = Δθ / Δt`
  - `播放速率 = ω / PLATTER_OMEGA`
  - 1 = 正常碟速，0 = 手停声停，**负值 = 倒放**。
- 速率经 0.55 系数平滑，限幅 ±2，避免抖动。
- 手停住（约 80ms 无移动）→ 速率平滑到 0。
- **暂停时搓碟**：临时启动 source 出声（模拟 CDJ 手转碟片发声），松手后停在该位置；播放中搓碟，松手恢复正常速度。

**技术实现**

- `Deck`：`scratchBegin()` / `setScratchRate(rate)` / `scratchEnd()`；`scratchBegin` 在暂停时调用 `_start()` 临时出声。
- 位置积分 `_flushPos()`：`_pos += dt × playbackRate`（playbackRate 可为负），因此位置随搓碟正反向移动。
- 已验证 `AudioBufferSourceNode.playbackRate` 支持负值（Chrome 实测 set -1 → readback -1，反向播放）。
- `DeckPanel`：转盘 `pointerdown/move/up`，`atan2` 计算指针角度，处理 ±π 跨边界。

**验证**

- seek 到 8s 后慢速逆时针搓碟：`playbackRate` 变为 -0.5 ~ -0.64，位置从 8.22 连续回退到 8.10（倒放）。
- 松手后停在当前位置，无鬼叫。

### 3. 段落标签：保持自动检测（不改）

**说明**

- 右上角 SECTION（Intro / Build / Drop / Break / Groove）由**启发式算法自动检测**，无需手动切换：
  - 基于低频能量的「短窗均值 vs 长窗均值 vs 更早均值」对比，叠加位置（前 15s 为 Intro）。
  - 标签切换有 1.2s 迟滞，避免抖动。
- 用户确认此项**不改**。

### 4. 大屏 VJ 视觉强化

**v1 问题**

- 大屏图形偏小、偏暗，频谱驱动幅度弱，视觉上像装饰而非「LiveHouse 的主视觉」。

**v2 方案**

- Canvas2D 重写 4 种视觉，图形铺满、高饱和、多层叠加：
  - **Spiral 螺旋**：多层同心螺旋，随频谱扰动、节拍脉冲。
  - **Wave 波形**：多层波形填充，随音频大幅起伏。
  - **Spectrum 频谱**：镜像频谱柱，节拍时全屏闪光。
  - **Tunnel 隧道**：随节拍推进的霓虹隧道。
- 节拍全屏闪光、频谱大幅驱动、Bloom 后处理增强发光。
- 大屏在场景中放大到 **18 × 9**，并新增**两侧副屏**（复用同一画面），成为视觉主体。
- 用户明确：不需要全屏预览。

**技术实现**

- `StageScreen.js`：离屏 Canvas 2D（1024×512），每帧绘制；`StageScene` 替换主屏 geometry 为 18×9，并用同一 `texture` 建左右副屏。

**验证**

- 播放时大屏明显变亮、随节拍闪光与频谱扰动；切换 4 种模式均正常。

### 7. 演唱会舞台 + 人形观众 + 镜头 + 震动

**v1 问题**

**v2 方案**
